# Stakeholder Matrix and RACI

Datindo is a **prospective** partner only. No Datindo employee, issuer, legal reviewer, or financial advisor is assigned to this project as of this document.

R = execute; A = accountable; C = consult; I = informed. Roles below are proposed, and solo developer can fill multiple internal roles with documented conflict-of-review limitations.

| Task | Founder/PO | Software engineer | External market expert | Security reviewer | Prospective user |
|---|---|---|---|---|---|
| Scope/priority | A/R | C | C | I | C |
| Regulatory clause signoff | C | I | A/R | I | C |
| Synthetic fixtures | A | R | C | I | I |
| Calculation design | A | R | C | I | C |
| Engine truth-table approval | C | R | A | I | C |
| API & UX | A | R | C | C | C |
| AI document workflow | A | R | C | C | C |
| Security controls | A | R | I | C/R | I |
| Customer data permissions | A/R | I | C | C | R (data owner) |
| Pilot agreement | A/R | C | C | C | C |

## Stakeholder interview guide
1. How is a monthly ownership snapshot reconciled, and by whom?
2. What is the current scenario-planning tool (Excel, in-house, vendor)?
3. Which step delays Corsec/BAE work, and how often does it occur?
4. Which fields cannot lawfully leave client infrastructure?
5. What would make an analysis acceptable to review/audit?
6. What integration/file format is easiest for a pilot?
7. Who sponsors and signs procurement?

Do not invent or imply that these interviews have been completed.
